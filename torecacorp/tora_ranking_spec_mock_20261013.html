ガチャランキング機能（ランキングバトル）

2026-10-13 たたき台 v3（報酬の付与ルール・獲得商品での扱いを追加、集計間隔を固定化） ｜ 作成: パレットグループ トレカ商事カンパニー ｜ モック内の数値・ニックネーム・報酬はすべてダミーです

ガチャごとに「期間中の消費pt」で順位を競い、上位者に報酬を付与する機能です。いただいた要望に対する仕様方針を下表にまとめ、方針が決まっていない点は確認事項として後半に列挙しました。運用上必要になる「集計の確定と不正チェック」は弊社から追加しています。

SPEC 1

ランキングの単位と集計ルール

ランキング単位ガチャ単位（1つのガチャに1つのランキング）。内部的には scope = gacha / global の項目を持たせ、全体バトル（期間中にランキングONの全ガチャを合算）は同じテーブル・同じ画面部品で追加できる設計にする。
順位の指標集計期間内にそのガチャで消費したpt（コイン）の合計。無料ガチャ・配送専用ptなど消費対象外の支払いは含めない。
集計期間ガチャごとに開始・終了日時を設定。初期値はガチャの公開期間。期間外の消費はカウントしない。
同点の扱い同ptの場合は先にそのptへ到達したユーザーを上位とする（最終消費日時の早い順）。表示上は同順位にしない。
減算ガチャの取り消し・返金があった場合は、該当ptを集計から差し引く。
対象外ユーザー凍結中アカウント、運営・テスト用アカウントは集計対象外（順位表に出さない）。

SPEC 2

開催中の見せ方（トップ・ガチャ詳細）

トップ一覧のカードサムネイル上部には還元率表記が入るため、ラベルは上に置かない。画像下端の帯（販売前に「販売開始まで 05:28:57」が出る黒帯と同じ位置）を赤帯に変え、「ランキングバトル開催中」の文言のみを表示する（終了タイマーは出さない）。SPは1カラム、PCは2カラムの現行レイアウトのまま。
販売開始前既存の「販売開始まで」黒帯を優先し、カード下部（価格・残り口数の下）に小さく「ランキングバトル対象」ラベルを出す。販売開始と同時に開催中の帯へ切り替わる。
終了後終了〜確定までは帯を「ランキングバトル 集計中」、確定後は「結果発表中」を7日間表示して外す（日数は要確認）。
終了日時の見せ方カードにはタイマーを出さず、ガチャ詳細のバトル帯とランキング欄に集計期間（10/20 12:00〜10/31 23:59）を表示する。
ガチャ詳細の上部メインバナーの直下にバトル帯（「ランキングバトル開催中」＋集計期間）を表示。右端に「あなた 14位 ▶」チップを置き、タップでランキング欄へスクロール。
ランキング欄の位置重要事項（総還元率の算定基準）→ 購入制限 → 宝箱ゲージ注記 の下、ラインナップの上に挿入。
スクロール対策（SP）画面下部に固定されている購入エリア（価格・残り口数・ガチャボタン）の上に、1行の順位バーを追加:「あなた 14位 ｜ 10位まであと 2,601pt　ランキングを見る ▲」。タップでランキング欄へスクロールし、ランキング欄が画面に入っている間はバーを隠す。
PCの見せ方現行はPCでも中央にスマホ幅のカラムで表示され左右が空いているため、画面幅1100px以上ではカラム右側にランキング（上位10件＋自分の状況）を追従表示する。順位バーはPCでは出さない。本文中のランキング欄はSPと同じ位置に残す。

SPEC 3

ランキング欄の表示内容

表示件数上位10件（順位・アイコン・ニックネーム・消費pt）。1〜3位はメダル色で強調。11位以下は一覧に出さない。
自分の状況順位表の下に常設: 自分の順位／自分の消費pt／ランクインまであと○pt（＝現在の10位のpt − 自分のpt ＋1）。ランクイン中は「ひとつ上の順位まであと○pt」に切り替える。未参加は「1回引くとランキングに参加できます」。
配信への配慮自分の消費ptは配信画面に映り込みやすい個人の課金情報のため、初期状態は伏せ字（●●●pt）とし、タップで表示する。順位と「あと○pt」は常時表示。
報酬・期間順位表の下に報酬一覧（例: 1位 ○○ ／ 2〜3位 ○○）と集計期間・最終更新時刻を表示。
ニックネーム未設定「ユーザー＋ID下4桁」で表示する。ランキング欄には設定導線を置かない（設定はマイページから）。

SPEC 4

ニックネーム・アイコン設定

設定場所マイページ ＞ プロフィール。
ニックネーム2〜10文字。絵文字・URL・電話番号形式は不可。NGワード辞書（運営が管理画面で追加可）に一致したら保存不可。重複は許可。
変更制限変更は24時間に1回まで（ランキング上での成りすまし・荒らし対策）。
アイコン運営が登録したデフォルトアイコン（3〜5種）から選択、またはユーザー自身の画像をアップロード。アップロードはJPG / PNG / WEBP・5MBまで、サーバー側で正方形にトリミングし縮小（256px程度）して保存する。未設定はデフォルトの1つ目。
アップロード画像の扱いアップロードは即時反映し、問題のある画像は運営が事後にリセットする運用を想定（事前承認制にする場合は承認待ちの間デフォルトアイコンを表示）。
運営側の操作管理画面のユーザー詳細から、ニックネーム・アイコンの強制リセット（初期状態に戻す）ができる。デフォルトアイコンの追加・差し替えも管理画面で行う。

SPEC 5

更新方式（リアルタイムか定期集計か）

完全なリアルタイム配信は、同時接続数が多い配信中や新弾公開直後に負荷が集中します。ユーザーが最も気にする「自分のpt」は即時に反映し、順位表だけを短い間隔で集計する案を推奨します。

方式自分のpt順位表負荷・コスト評価
A. 完全リアルタイム（プッシュ配信）即時即時ガチャを引くたびに全閲覧者へ配信。配信中の同時アクセスで負荷大非推奨
B. ハイブリッド（推奨）即時（ガチャ結果と一緒に返す）1分ごと（固定）に集計、画面は表示中のみ再取得集計は1分に1回。閲覧者数が増えても負荷はほぼ一定推奨
C. 定期集計のみ5〜15分ごと5〜15分ごと最小自分のptが増えないように見え問い合わせ要因になる
集計間隔全ガチャ共通で1分ごと（固定）。ガチャ単位で間隔を選ぶ設定は設けない。画面には「最終更新 15:02（1分ごと）」と表示する。
期間終了時終了日時ちょうどで最終集計を行い、順位を暫定確定として固定。以降は表示が「集計中」→ 運営の確定後「最終結果」に変わる。

SPEC 6

管理画面: ガチャ単位のON/OFFと報酬設定

設定場所ガチャ（オリパ）編集画面に「ランキング」タブを追加。
ON/OFFガチャ単位のトグル。期間中にOFFにした場合は表示を止めるだけで、集計データは保持する（再度ONで復帰）。OFFのガチャはトップの帯・ラベルも出さない。
設定項目集計期間（開始・終了）／結果発表の表示日数／報酬スロット。表示件数（10件）と集計間隔（1分）は固定。
報酬スロット最大10行。各行に対象順位（○位〜○位）と報酬を設定する。報酬は景品カードかコイン付与。景品カードはガチャの景品登録と同じルールで、カードDBから選び、状態・交換コイン・配送限定を設定する（配送限定ONなら交換コインは設定不可）。
順位の範囲が重なる行は保存不可。1位〜10位に1行ずつ設定する使い方も、「4〜10位」のようにまとめる使い方もできる。
期間中の変更集計期間が始まった後は、報酬内容の変更時に確認を挟み、変更履歴（日時・操作者）を残す。

SPEC 7（弊社追加）

結果の確定と報酬付与

ランキング報酬は複数アカウントでの上位独占を誘発しやすいため、終了と同時に自動付与せず、運営が一度確認してから付与する流れを提案します。

流れ期間終了 → 暫定結果を自動集計 → 運営が結果画面で確認 → 必要に応じて除外 → ［結果を確定して報酬付与］ → ユーザーにお知らせ通知
確認用の表示上位者ごとに注意フラグを出す: 凍結済み／同一の決済手段を使う別アカウントあり／同一端末からのログインあり／登録から7日以内。
除外と繰り上げ除外したユーザーは順位から外し、下位を繰り上げる（繰り上げの有無は設定で選択）。除外理由を記録する。
確定の期限終了から2営業日以内に確定・付与する運用を想定（期限はユーザー画面に「11/2までに付与」と表示するため事前に決めておく）。
付与確定操作で一括付与。詳細は SPEC 8。
履歴確定後の結果・除外理由・付与記録はガチャごとに閲覧可能（CS対応用）。

SPEC 8（弊社追加）

報酬の付与と獲得商品での扱い

報酬の景品カードは、ガチャで当たった景品と同じ扱いに統一します。運用・CSのルールを分けずに済むようにするためです。

確定待ち（ステイ期間）の表記終了〜確定までの間、ガチャ詳細のバトル帯とランキング欄に「集計中：結果確定・報酬付与は11/2までに行います」を表示。自分の欄には「報酬対象（暫定）: ○○」または「今回は報酬対象外です（暫定）」を出す。トップのカード帯は「ランキングバトル 集計中」。この期間、獲得商品には何も追加しない。
確定後の表記ランキング欄は「最終結果」に切り替え、自分の欄に「○○を付与しました」と付与先を案内。あわせてお知らせ（サイト内通知）で上位者に付与を伝える。
景品カードの付与先ガチャ景品と同じく獲得商品の「未選択」に追加。ユーザーは「発送する」か「コインに交換」を選ぶ。
配送限定品配送限定の報酬も「未選択」に入る（ガチャと同じ）。交換ボタンは出さず「発送する」のみ。
48時間の自動交換交換可の報酬は、ガチャ景品と同じく付与から48時間で交換コインに自動交換。起点は期間終了時ではなく付与（確定）時刻。付与のお知らせに「48時間以内に発送か交換を選んでください」と明記する。配送限定品は自動交換の対象外。
コイン付与の報酬獲得商品には入れず、確定時に所持コインへ直接加算。コイン履歴に「ランキング報酬（SAR確定 漆黒オリパ 5位）」として記録。
ランキング報酬の識別獲得商品の各行に入手区分を持たせ、「ランキング報酬」バッジと入手元（どのバトルの何位か）を未選択・発送待ち・発送済みのすべてで表示。［ランキング報酬のみ］の絞り込みを追加。ガチャを引いた記録ではないためガチャ履歴には出さない。
管理側の識別配送管理・獲得商品の一覧に入手区分（ガチャ／ランキング報酬）の列とフィルタを追加。対象ランキングと順位から元の結果画面に辿れるようにする。

確認事項（ご判断いただきたい点）

TORA様へ確認
  1. 全体バトルの扱い: 10月はガチャ単位のみで良いか。全体バトルを同時に出す場合、対象ガチャの選び方（ランキングONの全ガチャ／個別に指定）。
  2. 「10スロット」の意味: 1〜10位に1つずつ報酬を設定する意味か、順位範囲つきの報酬行を最大10行持てる意味か（本資料は後者で設計。前者の使い方も可能）。
  3. 報酬の種類: コイン付与・景品カード以外に必要なもの（称号、限定ガチャ参加権など）はあるか。
  4. 順位の指標: 消費ptの合計で良いか（引いた回数ではなく金額ベース）。課金額消費タイプのガチャも同じ扱いで良いか。
  5. 自分の消費ptの伏せ字表示: 配信者の利用を考え初期は伏せる案としたが、常時表示を希望されるか。
  6. 終了後の「結果発表中」表示の日数（本資料は7日）と、トップで開催中ガチャを上位に並べる（並び替え・タブ追加）かどうか。
  7. PCの右側追従表示: 実装範囲に含めるか（含めない場合はPCもSPと同じ順位バーで対応）。
  8. アップロードアイコンの審査: 即時反映＋事後リセットで良いか、事前承認制にするか。
  9. 結果確定の運用担当と期限: TORA様運営側で除外判断・確定操作を行う前提で良いか。終了から何日以内に付与するか（本資料は2営業日）。
  10. 報酬の自動交換: ガチャ景品と同じ「付与から48時間で自動交換」で良いか（起点は付与時刻）。
刀根さんへ確認（実装）
  • ガチャ結果APIで自分の累計ptと順位を返す改修の可否（推奨案Bと順位バーの前提）。
  • トップ一覧APIにランキング状態（開始前／開催中／集計中／結果発表）と終了日時を追加できるか。
  • 順位集計を1分ごと（全ガチャ共通）のバッチで回した場合のDB負荷。
  • 獲得商品に入手区分（ガチャ／ランキング報酬）と入手元を持たせる改修範囲と、48時間自動交換の処理をランキング報酬にもそのまま適用できるか。
  • 取り消し・返金時のpt減算を既存の取り消し処理に組み込めるか。不正チェック用フラグ（決済手段・端末の重複）を既存データから出せる範囲。
